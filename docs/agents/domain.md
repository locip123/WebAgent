# Domain docs

This repository uses a single domain context.

Before exploring or changing a domain area:

- Read the root `CONTEXT.md`.
- Read relevant ADRs under `docs/adr/` when present.
- Use canonical terms from the glossary in issues, tests, and code.
- Surface conflicts with an existing ADR instead of silently overriding it.

Missing domain files are not blockers. Create glossary entries and ADRs lazily
through the domain-modeling workflow when decisions actually crystallize.
