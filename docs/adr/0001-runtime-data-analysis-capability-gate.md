# 以运行时可用就绪数据目录门控数据分析助手

<!-- Status: accepted -->

数据分析助手仅在当前任务存在至少一个可用就绪数据目录时向模型公开；该集合是运行时已注册的 `ready_data_dir` 减去被静态拒绝的目录。门控同时收窄标准及首轮探索决策的严格输出 Schema 和 `ACTION CONTRACT`，并把开放状态下的 `data_dir` 收窄为该集合。没有可用目录时，`downloads/` 下的文档路径不得被当作分析工件；若旧缓存或非严格提供商仍返回该动作，执行器在任何路径更新持久化前拒绝整轮决策，以 `analysis_not_ready` 进入不消耗连续动作失败预算的恢复状态，并在后续提示中持续要求文档取证，直至观察到新的可用目录。

## Considered Options

- 仅提示“使用最新 ready_data_dir”——无法避免模型把下载文档误认为目录，也无法防止重复失败。
- 保留动作并在执行时拒绝——仍会让无效动作耗尽失败预算，并可能使同轮未经证实的路径进展落盘。
- 运行时能力门控——增加动态 Schema 与提示变体的维护成本，但把不可用能力从模型选择空间移除，并保持路径证据真实。

## Consequences

每次模型调用必须记录实际使用的能力变体。某个目录变为不可分析后，保留该次 `analysis_unavailable` 等原始诊断；若不存在其他可用目录，助手立即再次隐藏并在后续提示进入 `analysis_not_ready` 状态。新观察到的可用目录才会重新开放该能力。单纯未就绪不主动加入恢复提示；只有执行器实际拒绝了绕过门控的调用，恢复状态才持续注入后续提示。

非严格提供商若返回枚举外的 `data_dir`，这是数据目录契约违约：同一步要求结构化输出修复，不执行浏览器动作或路径更新，不能把它降级为 `analysis_not_ready` 或普通动作失败。

绕过“无可用目录”门控的调用会产生门控拒绝记录：它保留在轨迹中供审计，但没有浏览器副作用，不消耗浏览器步骤或连续动作失败预算；执行器随即在同一观察上以已收窄的能力契约重新决策。

能力变体按每个模型请求局部派生，全局动作契约保持只读，避免并发任务相互隐藏能力。

`data_dir` 枚举完整包含全部可用目录，不设静默截断上限；若 Schema 规模需要优化，必须以新的不透明工件 ID 协议显式替代。

实现验收至少覆盖：标准与首轮 Schema/提示契约在无候选时都不暴露分析动作；门控拒绝不提交路径、不消耗浏览器步骤或动作失败预算且产生持续恢复状态；新候选重新开放能力，静态拒绝保留原始诊断；开放时仅接受完整候选枚举；并发任务间的能力状态相互隔离。
