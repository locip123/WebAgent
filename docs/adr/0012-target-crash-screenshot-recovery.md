# 目标崩溃截图故障立即交给会话恢复

## 背景

真实评测中 `Page.screenshot: Target crashed` 曾被观察层当作普通截图异常处理：先等待 180 秒，再在同一失效页面上重试，随后继续无截图观察。这样既浪费任务截止时间，也阻止 agent 及时选择存活标签页或隔离损坏 worker。

## 决策

截图链区分生命周期故障和暂时性截图故障：

- `Target crashed`、`TargetClosedError` 及页面/上下文/浏览器关闭错误立即向 `ProtocolIIIAgent` 传播；agent 只对已接管的存活标签页执行零配额重新定锚。找不到存活页时结束当前任务并让 runner 回收 worker。
- 普通截图超时或可恢复协议错误保留一次完整截图链重试，但等待固定 3 秒；第二次失败可以继续文本观察。
- 标注截图阶段再次遇到生命周期故障同样立即传播，不能用原始截图掩盖会话已失效。

## 结果

目标崩溃不再消耗 180 秒的无效等待，且不会把死页面误传给模型。短暂的合成器或 CDP 抖动仍有一次重试机会；截图持续不可用时，文本检索能力保持向后兼容。
